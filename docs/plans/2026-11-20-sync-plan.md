# Opt-in End-to-End Encrypted Sync (#781)

Step M6 of [User data: device continuity and sync](../architecture/user-data-sync.md).

## Overview

Carry user state between a user's devices over the internet, across iOS and Android, within about a second while both are online. Sync is off until the user turns it on. A relay orders, stores, and fans out encrypted frames; it never sees op values, keys, or titles.

## Prerequisites

- M1 to M5 are done: stable keys, HLC, user state collections, outbox, snapshot format, `SnapshotMerger`, `RestoreProjector`, continuity snapshot.
- The outbox already holds the latest value of each changed field, and the snapshot already carries every row with its clocks. Sync is mostly transport, keys, and the receive path.

## Decisions

| ID | Topic | Decision |
|----|-------|----------|
| P1 | Server storage | The relay stores opaque frames by `seq`, plus the latest compacted snapshot and the `seq` it covers. Devices upload a new compacted snapshot (encrypted, the M5 format) when the frames after the last one pass a size threshold; the relay then drops frames the snapshot covers. This replaces the per-op `op` table of the design doc: per-field compaction on the server would need per-op metadata, and a blind server with per-frame encryption cannot compact by field |
| P2 | Authentication | `authSecret` = HKDF-SHA256(sync key, "audiflow-sync auth v1"). The relay stores SHA-256(`authSecret`) as the `sync_key` verifier. Enrolling a device sends `authSecret` over TLS once and gets a random per-device token, stored hashed; every later `hello` uses that token. Revocation clears the token and replaces the verifier |
| P3 | Key wraps | `wrapKey` = HKDF-SHA256(sync key, "audiflow-sync wrap v1"). The `sync_key` wrap seals {data key, key version} under `wrapKey`; the QR code and the recovery code both carry the sync key, so one wrap serves both, and a joining device gets the data key from it in `welcome`. Each device also has an X25519 key pair: the private key stays in device-only storage, the public key is registered at `create` or `enroll`. A device wrap seals {sync key, data key, key version} to a device's public key (ephemeral X25519, HKDF-SHA256 over the shared secret and both public keys, then XChaCha20-Poly1305), so any remaining device can seal one for every other device during a revocation. Device wraps exist only after a revocation; until then every device already holds the current secrets |
| P4 | Ciphers | XChaCha20-Poly1305 for frames and wraps (24-byte random nonce), HKDF-SHA256 for derivation, from the `cryptography` package (pure Dart; `cryptography_flutter` later if profiling asks). Frames carry `algId` and `keyVersion`; the AEAD's associated data is accountId, `algId`, and `keyVersion`, so a frame cannot be replayed into another account or key version |
| P5 | Frame contents | One frame is a batch of ops: the same one-field entity messages, with clocks, that the snapshot body uses, grouped by entity, plus the sender's `deviceId`. The receiver merges them with the `SnapshotMerger` rules, so a frame and a snapshot of the same state merge to the same result |
| P6 | Protocol | JSON text messages over one WebSocket; binary payloads base64url. `hello` carries `protocolVersion`; the relay answers with the minimum it supports. Message list below |
| P7 | Pairing payload | QR: `audiflow-sync:1:` + base64url(accountId 16 B, sync key 32 B). Recovery code: the same 48 bytes plus a 2-byte checksum in Crockford base32: 80 characters, shown in 20 groups of 4. Neither carries the data key; it comes from the `sync_key` wrap |
| P8 | Key storage | iOS: Keychain, `kSecAttrAccessibleAfterFirstUnlock`, synchronizable for the sync key (C2) and not synchronizable for the data key, the device private key, and the token. Android: Block Store with cloud backup for the sync key; EncryptedSharedPreferences-backed secure storage for the data key, the device private key, and the token. Through `flutter_secure_storage` on iOS and a small Kotlin channel for Block Store |
| P9 | Joining adopts the history | Joining an account adopts its `historyId` (design doc, Histories). A device with data merges the account snapshot and the frames after it first, then pushes its full state as ordinary frames (so devices already online merge it), and once those are acknowledged uploads a compacted snapshot covering them. Nothing the outbox dropped while sync was off is lost |
| P10 | Connection lifetime | Open while the app is in the foreground or playing; closed otherwise. Background feed sync does not open it |

## Protocol (version 1)

Client to relay:

| Message | Fields | Use |
|---------|--------|-----|
| `create` | accountId, authVerifier, syncWrap, device {deviceId, name, platform, publicKey} | First device creates the account |
| `enroll` | accountId, authSecret, device {deviceId, name, platform, publicKey} | A device joins with the sync key; it needs nothing it does not have yet, and gets the data key from `syncWrap` in `welcome` |
| `hello` | protocolVersion, accountId, deviceId, token, cursor | Every connection after enrollment |
| `push` | frames [{clientId, blob}] | Send outbox batches |
| `snapshot` | coversSeq, blob | Upload a compacted snapshot |
| `presence` | blob | Encrypted "playing X at 12:34"; held in memory, never stored |
| `revoke` | deviceId, newAuthVerifier, newSyncWrap, deviceWraps {deviceId: blob} | Run from a remaining device, which seals a wrap to each other remaining device's public key |

Relay to client:

| Message | Fields |
|---------|--------|
| `welcome` | minProtocolVersion, token (after create or enroll), syncWrap, deviceWrap (when a revocation left one for this device), snapshot {coversSeq, blob} after `enroll` and when the cursor is older than it, devices {deviceId, name, platform, publicKey} |
| `frames` | [{seq, deviceId, blob}] |
| `pushed` | [{clientId, seq}] |
| `stored` | coversSeq: the uploaded snapshot is kept and the frames it covers are deleted. It acknowledges storage only: outbox ops are deleted on `pushed`, for the frames that carried them, and only when their clocks are unchanged |
| `presence` | deviceId, blob |
| `error` | code (`unauthorized`, `revoked`, `tooOld`, `rateLimited`, `invalid`) |

## Owner actions

Code for every PR lands without these; they gate turning sync on for users.

- A Cloudflare account, the deploy of `relay/`, and the relay URL per flavor.
- Running the relay tests in CI: a workflow change, which needs explicit approval.
- App Attest and Play Integrity setup in the Apple and Google consoles (M6g).
- Real-device acceptance tests of Keychain and Block Store migration and restore (after M7, as agreed).

## Acceptance (from #781)

- Two-device simulation tests: concurrent edits converge; an old device cannot resurrect an unsubscribed podcast; guid and URL keys for one show are joined.
- Position reaches the other device within about a second while both are online.
- The relay cannot read op values or keys.
- A revoked device can neither read new data nor re-enroll.
- Sync stays off unless the user turns it on.
