# Doc Kinds Manifest

Kind definitions consumed by `kusara`. The CLI loads `${KUSARA_DOC_ROOT}/kinds.md` at startup (default `KUSARA_DOC_ROOT=docs`); the YAML block below is the source of truth.

Schema semantics (`implements` / `depends_on` / `related` / `provides` / `modules`): invoke the `kusara:refs-schema` skill.

## Adding a new kind

1. Add an entry to the YAML block.
2. Add `index.output` if a generated INDEX is wanted.
3. Run `kusara validate`.

## Manifest

```yaml
kinds:
  - name: fr
    path_globs: ["docs/fr/[0-9]*.md"]
    id_pattern: "fr:{slug}"
    index:
      output: docs/fr/index.md

  - name: architecture
    path_globs: ["docs/architecture/[a-z]*.md"]
    id_pattern: "arch:{slug}"
    index:
      output: docs/architecture/index.md

  - name: integration
    path_globs: ["docs/integration/*.md"]
    id_pattern: "integration:{slug}"

  - name: package
    path_globs: ["packages/*/CLAUDE.md"]
    id_pattern: "pkg:{name}"
    index:
      output: packages/index.md

  - name: index
    declared_via: generated
    id_pattern: "index:{kind}"
```

## Reserved kind: `index`

Files generated by `kusara index` carry `kind: index` and are never hand-edited. Their `provides:` enumerates the IDs they index over.
